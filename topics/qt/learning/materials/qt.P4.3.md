# P4.3：模型的数据变了，视图怎样知道？

课次：`qt.P4.3`。准备与资料核对：2026-10-20。来源 ID：`qt-item-model`、`qt-table-model`、`qt-model-index`。建议结合表格与代码阅读约 8～12 分钟，按自己的节奏即可。

本课目标是：修改已有单元格后，能让模型报告正确的变化位置，并解释为什么这样报告。读完后再讨论概念，最后回到 `resultmodel.cpp` 做小实践。现在先阅读；阅读时间和读完材料都不代表已经掌握。

## 从已有程序连起整条路径

你的 `ResultModel` 内部有一个 `results_` 容器，每个元素保存姓名和分数。`QTableView` 负责显示。它通过模型接口取数，不直接访问这个私有容器。

| 行号 | 第 0 列：姓名 | 第 1 列：分数 |
|---|---|---|
| 0 | alpha | 91 |
| 1 | beta | 84 |
| 2 | gamma | 96 |

可以把一次显示过程理解为：视图询问表格有多大，再询问需要显示的格子。`rowCount()` 和 `columnCount()` 提供尺寸；`data()` 按位置和用途提供值。实际调用顺序和次数由 Qt 决定，这里描述的是职责关系。

`view.setModel(&model)` 建立视图与模型的联系。构造函数已经放入三条数据，所以初始显示不需要再插入三行。已有的 `rowCount`、`columnCount`、`data` 实现将它们暴露给视图。

本练习是平坦表：根下面有三行，单元格下面没有子项。因此，以默认的无效 `QModelIndex()` 作为根来询问时有三行；以某个有效单元格作为 parent 询问其子行数时是零。这里的 parent 是模型层级关系，与 `QObject` 管理对象寿命的 parent 是两回事。`QAbstractTableModel` 已提供平坦表所需的 `index()` 和 `parent()` 默认行为。[官方表模型说明](https://doc.qt.io/qt-6/qabstracttablemodel.html#subclassing)

## 先定位，再取值

`QModelIndex` 表示模型中的位置。对这张表，使用 `model.index(row, column)` 定位，参数顺序始终是**先行、后列**；行列编号从零开始。[官方索引说明](https://doc.qt.io/qt-6/qmodelindex.html#details)

例如，`model.index(1, 0)` 定位到 beta 的姓名格。索引本身不是姓名字符串，取值还需要调用模型的 `data()`：

```cpp
const QModelIndex cell = model.index(1, 0);
const QVariant value = model.data(cell, Qt::DisplayRole);
const QString text = value.toString();
```

这是三个不同动作：找到位置、按用途取值、把通用返回值转成字符串。在当前数据下，`text` 是 `beta`。

`Qt::DisplayRole` 表示“用于显示的值”。同一个位置还可以被询问背景色、提示文字等用途；本练习只实现显示用途。`QVariant` 能容纳不同类型，因此同一个 `data()` 接口可以在姓名列返回字符串、在分数列返回整数。这里的行列确定位置，role 确定用途。[官方 data 接口](https://doc.qt.io/qt-6/qabstractitemmodel.html#data)

## 写入数据与通知变化各做一件事

假设把某个已有分数从 91 改成 100。写入容器之后，模型下一次被询问该值时就能返回 100。但 Qt 不会监控普通 C++ 容器成员的每次赋值。需要模型明确告诉使用者：哪些已有数据变化了。

本课使用 `dataChanged` 信号。它报告变化位置，视图随后可重新取值和更新显示。通知中不携带替代 `data()` 的新分数。

```text
业务操作
   ↓
修改模型内部数据
   ↓
模型发出 dataChanged，报告变化位置
   ↓
视图按需要重新取值、更新显示
```

不要把“没发通知”理解成“底层值没有改变”。也不要依赖“界面肯定一直显示旧值”这个绝对判断：其他原因引起的重新取值可能偶然显示新值。缺少通知的问题是，视图无法可靠地及时得知此次变化。

顺序也有意义：**先让数据成为新状态，再通知使用者读取它。** 发信号时，接收者可能立即查询模型。若先通知后赋值，它在那一刻读到的仍是旧值。[官方 dataChanged 契约](https://doc.qt.io/qt-6/qabstractitemmodel.html#dataChanged)

## 两个端点描述一个区域

信号的主要参数是：

```cpp
dataChanged(topLeft, bottomRight)
```

两个参数都是 `QModelIndex`，分别定位受影响区域的左上角和右下角。范围包含两个端点；它们必须属于同一个 parent。平坦表中的这些格子都处于根层。[官方范围定义](https://doc.qt.io/qt-6/qabstractitemmodel.html#dataChanged)

先用另一张库存表示范，避免把例子直接当作待做函数的答案：

| 行号 | 第 0 列：商品 | 第 1 列：库存 |
|---|---|---|
| 0 | pen | 12 |
| 1 | book | 8 |

假设业务已经更新了第 0 行的商品名称和库存，两列显示值都变化了。模型成员函数中的通知可以写成：

```cpp
const QModelIndex first = index(0, 0);
const QModelIndex last = index(0, 1);
emit dataChanged(first, last);
```

第一行定位第 0 行第 0 列，第二行定位同一行的第 1 列。第三行报告这一行的两个格子需要重新查询。`emit` 是 Qt 表达“发出信号”的写法；这里调用的是继承而来的信号。

若变化区域只剩一个格子，矩形就缩成一个点，左右端点都定位到它。若连续多行的同一列变化，矩形会变成一条竖线：行号不同，列号相同。端点并不分别代表旧位置与新位置。

想范围时，可以先用笔圈出变过的格子，再找包住它们的左上角和右下角。第一个参数跟着表格的纵向行号，第二个参数跟着横向列号。不要因为平时习惯 `(x, y)`，就把 `index(row, column)` 的顺序调换。

## 范围、角色与无效输入的边界

姓名列和分数列都有显示意义。一次修改只影响其中一列时，通知范围取决于**这次修改影响的格子**。把没有变化的相邻格也包含进去，可能仍能看到正确结果，但会让使用者处理额外范围；本课练习要求精确报告。

`dataChanged` 还有可选的第三个参数 roles，用于说明哪些用途的数据变化了。省略时按所有用途可能变化处理。它不是行号、列号或新值。本课沿用已有的两参数写法，先把位置与时序学扎实。[官方参数说明](https://doc.qt.io/qt-6/qabstractitemmodel.html#dataChanged)

另外，业务函数接收到的行号不一定有效。三行数据的合法行号是 0、1、2；负数和 3 都越界。应在访问容器和发通知之前处理无效输入。通知既不修复越界，也不负责写入数据。

本课只改变已有单元格的值，表格尺寸保持不变。新增行会涉及结构变化，另有对应协议，暂时无需扩展。练习目录名中的 readonly 表示用户当前不能直接在视图里编辑格子；程序仍可通过模型的业务函数更新数据。

## 带着这条路径结束阅读

把整件事连成一句话：业务代码修改模型内部值，模型报告变化位置，视图再通过模型接口读取显示数据。位置、数据、通知在同一条路径上承担不同职责。

稍后的讨论会结合具体变化范围确认这条路径；之后的实践回到现有模型，完成一个有边界检查的业务更新函数，并运行已有检查。当前保留 `setScore()` 和 `setName()` 的原样，不要求现在动手。

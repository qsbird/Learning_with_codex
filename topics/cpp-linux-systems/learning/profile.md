# C++ Linux Systems 学习档案

## 目标与约束

- 职业定位：具备 CAE/大型工业软件经验的 Linux C++ 系统与工程数据处理工程师。
- 主出口：工业软件平台、CAE/CAD 前后处理、工程数据管理与异步任务。
- 次出口：Linux C++ 网络服务、中间件和基础组件。
- 计划周期：2026-09-14 至 2027-09-12；必要时把市场验证延长至 2027-12-12。
- 每周时间：约 15.5 小时；工作日每天 1.5 小时，周末每天约 4 小时。
- 学习方式：以可运行代码、测试、解释和测量结果作为证据；阅读或编译成功本身不算完成。
- AI 边界：AI 可用于讲解、提示和评审；关键设计、首版实现和每月一次 90 分钟综合任务由学习者独立完成。

## 当前基础

- 正式 C++ 工程经历接近两年，覆盖车载中间件和 CAE 结构/流体仿真软件。
- 日常接触大型跨平台代码库、C++、CMake、Boost、Git 和 Qt；有独立模块、文档与 CI/CD 经历。
- CMake P0～P3 已完成，P4/P5 正在收口；Qt P0～P3 已完成，P4 正在进行；算法约有 100 道积累。
- 技术英语阅读能力可支持直接使用官方文档和英文资料。

## 当前缺口

- 现代 C++ 能读能用，但独立写出稳定的生命周期、内存与异常安全设计仍缺少证据。
- 模板与泛型实践不足；并发接近从零开始。
- Linux 系统编程、调试和故障定位经验不足。
- 缺少完整的“测量—定位—修改—复测”性能闭环。
- 使用 AI 后产出较快，但无 AI 的独立设计、编码和解释稳定性需要专门验证。

## M0 基线诊断

首次正式练习记录以下结果：

1. 在 90 分钟、无 AI 条件下实现一个拥有系统资源的 RAII 类型及必要测试。
2. 运行并记录当前 C++ 编译器、CMake、Ninja、GDB、perf、ASan、UBSan、TSan 的可用性和版本。
3. 用自己的话解释对象生命周期、拷贝/移动、异常路径和资源释放的关系。
4. 说明当前可用的 Linux 环境；若没有，先建立可重复的 Linux 虚拟机、容器或远程主机入口。
5. 选择一个可公开的练习主题和小型测试数据，不使用公司资料。

## 一年后的证据目标

- 独立实现并解释 RAII、移动语义、智能指针、异常安全和 STL 选型。
- 有界队列、线程池、取消/超时和优雅退出均有测试，并通过适用的 TSan 验证。
- Boost.Asio 异步 TCP 服务能处理 framing、部分读写、超时、断线和背压。
- 能使用 GDB、ASan、UBSan、TSan 和 perf 定位问题。
- 至少完成三次可复现的性能分析闭环。
- 完成一个独立仓库中的旗舰项目、至少六篇技术记录、六次模拟面试和五至十次市场试投。
- 算法代表题累计约 180～220 道，并能稳定复做常见中等题。

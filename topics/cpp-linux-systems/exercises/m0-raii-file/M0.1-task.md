# M0.1 实践：由对象负责释放文件

**本节环境：macOS 本机，C++20。** 当前不是 90 分钟无 AI 综合基线。复制、移动和自移动留待后续学习。

## 已准备的接口和语法

只需修改 `file_owner.cpp` 中构造函数与析构函数的两个函数体。`handle` 是传入的文件句柄，私有成员 `handle_` 用于保存它；两者都是 `file_api::Handle`，即 `std::FILE*`。`nullptr` 表示没有文件。

- 构造函数接管传入句柄的释放责任，外部代码随后不再关闭这个文件。
- 析构函数通过 `file_api::close()` 释放所管理的有效文件；没有文件时不调用关闭接口。
- `file_api::close()` 会实际关闭文件，并记录关闭、无效关闭次数，方便检查；请使用它，而不是绕过计数直接调用 std::fclose。

头文件和检查程序由教练提供，本节无需修改。头文件的 `explicit` 防止文件指针被隐式转换为 FileOwner；创建时明确写 `m0::FileOwner owner(handle)` 即可。两条 `= delete` 声明禁止复制，避免无意中让两个对象承担同一文件的释放责任；这些防护已提供，本节不要求实现移动。

## 你要完成的行为

1. 构造后文件仍保持打开，供拥有者的作用域使用。
2. 普通块结束、提前 return、异常被调用者捕获时，文件都恰好关闭一次。
3. 传入 nullptr 时不尝试关闭，不增加无效关闭次数。

`file_api::open()` 和 `close()` 的配对已提供；本题实现 FileOwner 如何接住这份责任。删除占位的 `(void)handle` 后写入自己的逻辑即可。不要改 `support/` 或 `check_scope.cpp` 来让检查通过。

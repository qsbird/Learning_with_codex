# 从一个命令行为读到源码

## 每次如何学习

使用仓库的 `learning-coach` 进行当次讲解、理解检查和练习。本课按学习者选择省略跨主题计划对账与后续复习安排。

1. 选一个问题，如“暂存后再修改，普通提交会使用哪个版本”。说明本次要能解释的行为。
2. 先讲实验需要的新概念、命令、参数和 C 写法。没有正向学习证据的内容都按新知识处理。
3. 用一个最小例子建立模型，等待学习者的复述或预测，再交付实践。
4. 由教练准备一两个文件、少量提交的隔离实验仓库；学习者只做与核心问题有关的操作。
5. 用命令检查内容、对象 ID、索引或引用，区分“终端看到了什么”和“据此能解释什么”。
6. 在固定 tag 的真实源码中找命令入口，只追当前场景所经的分支。每次先看少量关键函数，必要时再深入。
7. 学习者改变一个条件并解释结果；把本人操作、帮助程度、验证和解释记录到本课日志。

每次只调整一个难度维度。源码导航与环境准备由教练承担；学习者负责理解、预测、实验操作和解释。练习说明采用 Goal、Starting point、Prerequisite evidence、New syntax、Mini example、Predict、Task、Verify、Explain 的顺序。

## 怎样取得实现证据

| 层次 | 要回答的问题 | 证据 |
| --- | --- | --- |
| 命令语义 | 本次参数请求什么行为 | 对应版本的命令文档 |
| 仓库数据 | 哪些内容、对象或引用变了 | `show`、`cat-file`、`ls-files`、`rev-parse` 等当次输出 |
| 实现路径 | 哪个判断、回调或写入导致结果 | 固定 tag 下的文件与函数，注明中间省略步骤 |
| 运行验证 | 换一个条件后，解释还成立吗 | 学习者操作后的输出与解释 |

初期使用本机 Git 做行为实验，静态阅读上游源码；两者不是已经完成的单步调试证据。之后确有需要时，再按固定版本准备 Debug 构建。Trace2 用于观察已埋点事件与阶段；函数级调用和局部变量通过源码、断点及调用栈核对。

## 当次完成与记录

- 命令执行成功本身不等于学会。需要学习者操作证据及正确解释或小变体。
- 教练演示、资料准备和冒烟检查单独标注，不提升学习者能力状态。
- 菜单中只有达到出口证据的单元才可记为完成；完成课次按根目录约定记录并同步。
- 不生成“下周再做一次”、复习日期、提醒、逾期状态或跨主题任务。日志中的下一步只记可选入口，等待学习者再次提出学习请求。

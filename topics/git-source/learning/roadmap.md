# Git 源码选学目录

这是一份独立的兴趣课程菜单，不是日程表。无复习安排、截止日期或跨主题计划关联。所有单元当前均未开始；首课 `git-source.G1.1` 的阅读材料与实验脚手架已准备。

编号表示知识关系；可以选择感兴趣的命令，只在当次补齐必需概念。每个主题可拆成几次只研究一个行为的课次。验证输出须来自实验仓库，章节完成须有学习者操作与解释。

## G0 — 仓库模型与命令入口

- 起点：日常使用过 Git；内部模型尚无本课证据。
- 新知识：工作区、索引、对象、引用各自承担什么职责。
- 有界实践：观察一个提交的 commit、tree、blob；定位 `git.c` 中一个命令的注册与调用。
- 验证：`git cat-file -p HEAD`、`git ls-tree HEAD`、`git ls-files --stage`，命令先教再用。
- 出口：用自己的话串起文件路径、索引条目、blob 与提交；找到选定命令的 C 入口。
- 暂缓：对象压缩、哈希算法实现、完整启动流程。
- 可嵌入 G1.1 的开头，不要求单独完成后才能开始 G1。

## G1 — add 保存哪个时间点的内容

- 起点：G0 所需概念可在当次讲解；首课实验只有一个已跟踪文件。
- 新知识：暂存后继续编辑，索引内容不会自动随工作区更新。
- 有界实践：`git-source.G1.1`，暂存 B 后写入 C，完成普通索引提交并检查三个位置的内容。
- 验证：`git show HEAD:note.txt`、`git show :note.txt`、`Get-Content note.txt`、`git ls-files --stage`。
- 出口：本人操作与验证齐全；能在源码中指出读取文件、更新条目与写索引的职责，并预测再次暂存的影响。
- 暂缓：交互暂存、`-N`、过滤器、稀疏索引、缓存优化。
- 入口：[阅读材料](materials/git-source.G1.1.md)、[实验说明](../exercises/g1-add-snapshot/README.md)。

## G2 — commit 从索引形成历史

- 起点：已能解释一次普通暂存；需要时在当次补齐。
- 新知识：tree、commit 与分支引用更新的关系。
- 有界实践：创建两个小提交，比较树、父提交和分支引用；只阅读普通成功路径。
- 验证：`git cat-file -p HEAD`、`git ls-tree HEAD`、`git rev-parse HEAD HEAD~1`。
- 出口：解释每个提交如何连接快照与历史，以及为什么同一文件内容可由多个提交引用。
- 暂缓：签名、hooks、提交模板与提交图加速。

## G3 — status 与 diff 比较什么

- 起点：能区分 HEAD、索引、工作区。
- 新知识：不同状态或差异输出的比较两端。
- 有界实践：给同一路径留下已暂存和未暂存修改，分别观察三个位置；状态检查与差异输出可拆课。
- 验证：`git status --short`、`git diff`、`git diff --cached`、`git diff HEAD`。
- 出口：预测每条命令所见变化，并定位相关比较调用。
- 暂缓：文本 diff 算法、rename 检测、未跟踪缓存与性能优化。

## G4 — branch 与 switch 如何改变状态

- 起点：理解 commit 与引用；当次讲解符号引用。
- 新知识：创建分支和切换分支分别影响哪些状态。
- 有界实践：先创建同指向的分支，再在无未提交修改的条件下切换到不同提交。
- 验证：`git symbolic-ref HEAD`、`git show-ref --heads`、`git ls-files --stage` 与文件内容。
- 出口：画出切换前后 HEAD、分支与提交的关系，并指出工作区更新入口。
- 暂缓：worktree、多平台文件系统差异与脏工作区的全部保护规则。

## G5 — restore、reset 与 reflog

- 起点：能区分恢复文件与移动引用；缺少的概念当次先讲。
- 新知识：一次只选择一个命令模式，判断它的来源、目标和影响范围。
- 有界实践：分开研究 restore、reset 各模式与 reflog 定位；每次用新的隔离仓库，保留可恢复引用。
- 验证：所选模式前后的 `git rev-parse HEAD`、索引内容、文件内容及 `git reflog`。
- 出口：解释所选模式改变和保留了哪些状态，并用实验恢复一次误移的引用。
- 暂缓：过期策略、对象回收、路径 reset 与提交 reset 的全部组合。

## G6 — fetch、pull 与快进判断

- 起点：理解本地引用与提交图；当次补充远端跟踪引用、refspec 和 FETCH_HEAD。
- 新知识：获取数据与整合当前分支是不同步骤；先研究 `pull --ff-only`。
- 有界实践：用本地裸仓库和两个工作仓库，分别制造可快进和已分叉的历史；分次观察 fetch 与 pull。
- 验证：`git log --graph --oneline --all`、`git show-ref` 与 `git pull --ff-only` 的退出结果；拒绝时核对当前分支是否移动。
- 出口：解释获取后哪些引用改变，以及快进或拒绝发生在哪个判断。
- 暂缓：HTTP/SSH、协议协商、浅克隆与部分克隆。

## G7 — merge 与冲突条目

- 起点：能阅读分叉提交图；当次讲解合并基点、三方输入与索引 stage。
- 新知识：冲突是怎样记录为待解决状态的。
- 有界实践：同一小文件的同一行制造冲突，查看条目后再解决；只追一个冲突类型。
- 验证：`git merge-base`、`git ls-files --unmerged`、`git status` 与解决后提交的父节点。
- 出口：把 stage 1/2/3 对应到本实验的输入，解释解决后为何回到普通条目。
- 暂缓：完整 merge-ort 算法、目录重命名与复杂递归合并基点。

## G8 — push 与远端引用更新

- 起点：能区分本地分支、远端跟踪分支与远端仓库的分支。
- 新知识：推送请求与远端引用更新的约束。
- 有界实践：在本地裸仓库模拟远端，分别完成一次正常推送与一次非快进拒绝。
- 验证：`git ls-remote`、两端提交图和 `git push` 的结果；核对远端引用。
- 出口：解释客户端请求、接收端检查与引用变化，并在源码中区分两端职责。
- 暂缓：认证、托管平台保护规则、服务端部署、强制推送策略。

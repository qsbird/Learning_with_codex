# C++ 职业能力年度学习计划（2026–2027）

- 制定依据：2026-09-14 的职业画像与 C++ 学习路线
- 计划周期：2026-09-14 至 2027-09-12
- 可选市场延长窗口：2027-09-13 至 2027-12-12
- 最近校正：2026-09-16，依据本仓库实际路线和日志

## 1. 年度目标

职业定位：**具备 CAE/大型工业软件经验的 Linux C++ 系统与工程数据处理工程师**。

使用一套公共能力底座，保留两个出口：

1. 主出口：工业软件平台、CAE/CAD 前后处理、工程数据管理、异步任务与可视化集成；
2. 次出口：Linux C++ 网络服务、中间件和基础组件。

年度成功标准不是“课程看完”或某天立即获得特定薪资，而是形成可独立复现、可解释、可面试深挖的证据链：

- 现代 C++ 生命周期、所有权、异常安全、STL 与泛型能力；
- Linux 调试、并发、网络与性能分析能力；
- 一个持续 4～6 个月、有测试、架构文档和性能报告的旗舰项目；
- 三次性能闭环、六篇技术记录、六次模拟面试和五至十次市场试投；
- 约 180～220 道代表算法题达到可复做水平。

## 2. 原则与边界

- 继续在职学习，每周预算约 15.5 小时，不挪用睡眠时间。
- 用可运行代码、测试、解释和测量结果证明学习；阅读、抄写或一次编译成功不表示完成。
- 前六个月建立公共底座，第五至第六个月基于项目证据和岗位采样确定主投路线。
- AI 用于讲解、提示与评审；关键设计、首版实现和每月一次 90 分钟综合任务由学习者独立完成。
- 数学只补工程必需部分，不系统重学高数、线代和概率论。
- 不复制公司代码、数据格式、截图、架构、内部测量或其他敏感信息。
- 旗舰项目使用独立仓库；本仓库继续承担小课、验证实验和学习日志。

## 3. 当前仓库如何纳入计划

### CMake

当前 P0～P3 已完成，P4/P5 进行中。C0 前完成：

- `HELLO_BUILD_APP=OFF` 边界验证；
- targets export、package config 和独立 consumer；
- 从空目录重复 install/find_package 验证。

此后不再单独长期学习 CMake，而是在所有 C++ 项目中持续使用 target-based CMake、Presets、CTest、install/export/find_package。

### Qt

当前 P0～P3 已完成，P4.1 已完成，P4.2 脚手架存在。安排：

- C0 前完成只读二维模型、模型通知或事件分发解释；
- P5～P7 服务于文件处理、二维可视化和库边界；
- P8 与并发阶段合并，优先覆盖 worker-object、取消和关闭；
- P9/P10 放入旗舰项目后期，不再把简单控件堆叠作为主线。

### LLM

当前 M0～M2 已完成，M3 脚手架存在，M4 未开始。最多再使用两周、总计不超过五小时完成 M3/M4；此后暂停 BPE、微调、分布式训练等扩展，避免偏离 C++ 主线。

### C++ Linux Systems

新增 [cpp-linux-systems 主题](../topics/cpp-linux-systems/README.md)，统一承载现代 C++、Linux、并发、网络和性能小型练习。不要拆成五个互不连贯的 topic。

### 旗舰项目

暂定独立仓库 `engineering-data-lab`，目标结构：

```text
engineering-data-lab/
  libs/data-core/
  apps/data-server/
  apps/cli-client/
  apps/viewer/
  tests/
  benchmarks/
  docs/
```

M6 范围评审通过前不创建远程仓库。前期可保持 private，清除公司信息和敏感内容后再决定是否公开。

## 4. 每周固定节奏

| 星期 | 时间 | 固定职责 |
|---|---:|---|
| 周一 | 1.5h | 阅读本周核心材料，写预测、术语和一个待验证问题 |
| 周二 | 1.5h | 最小示例，只引入一个新概念并运行 |
| 周三 | 1.5h | 默认关闭 AI，独立完成本周关键代码或变体 |
| 周四 | 1.5h | 调试、测试、Sanitizer 或 benchmark；制造一个失败案例 |
| 周五 | 1.5h | 一道算法题复做；操作系统、网络、数据库轮换复习 |
| 周六 | 4h | 两个 90 分钟深度块；最后 60 分钟测试和文档 |
| 周日 | 4h | 90 分钟项目、60 分钟算法、60 分钟复盘/JD、30 分钟排下周 |

每个工作日的 90 分钟：10 分钟回忆，60 分钟唯一主任务，15 分钟验证，5 分钟记录。

### AI 使用规则

- 周一、周二可使用 AI 解释概念和审查计划。
- 周三默认关闭 AI；卡住 25 分钟后只请求提示，不请求完整实现。
- 周四先自行定位，再让 AI 提供第二意见。
- 周末提交前必须能逐段解释核心代码。
- 每月保留一次 90 分钟完全无 AI 的综合任务，记录完成比例与卡点。

## 7. 检查点

### C0 — 2026-09-27：现有仓库收口

- CMake P4/P5 的边界与 consumer 验证完成；
- Qt P4 完成并能解释模型契约、通知与事件分发；
- LLM M3 完成或记录唯一延期项；
- 所有完成项有日志和命令证据；
- 没有覆盖或混入已有未提交修改。

未通过时只顺延未完成练习，最多一周，不并行开启更多课程。

### C1 — 2026-12-06：现代 C++ / Linux 基线

- 无 AI 在 90 分钟内实现一个 RAII 资源类型和必要测试；
- 能解释拷贝/移动、智能指针、异常安全和 STL 选型；
- 独立用 GDB 定位一个崩溃；
- ASan/UBSan 对练习代码无已知错误；
- 至少完成 20 道算法题复做。

未通过时延长基础阶段 2～4 周，不进入复杂网络项目。

### C2 — 2027-02-28：并发 / 网络 / 性能门

- 有界队列、线程池、取消与优雅退出均有测试；
- TSan 压测无已知数据竞争或有明确限制；
- 异步 TCP 服务正确处理 framing、部分读写、超时与断线；
- 一份性能报告包含吞吐、p50/p95、CPU 和峰值内存；
- 工业软件和 Linux C++ 各采样 20 个 JD，并确定主投路线。

未通过时继续修复系统底座，不扩大旗舰项目功能。

### C3 — 2027-05-23：旗舰项目 v1.0

- Linux 和至少一个桌面平台能从空目录 configure/build/test；
- 服务端、CLI、测试和 benchmark 可运行；
- ASan/UBSan 无已知错误，并发部分有 TSan 证据或明确限制；
- README、架构图、协议、基准报告和 3～5 分钟演示完成；
- 能不看稿进行 10 分钟项目讲解。

未通过时冻结新功能，只修复构建、测试、性能证据和文档。

### C4 — 2027-06-20：年中市场验证

- 至少五个低风险试投或等量真实技术沟通；
- 记录简历通过率、技术面卡点和岗位匹配缺口；
- 基于反馈决定立即集中投递或延长到 2027 年底。

### C5 — 2027-07-18：专项能力与 v1.1

- 主方向新增一个可深入追问的复杂能力；
- 第三次性能闭环完成；
- 坏文件、断线、超时、取消、队列满和退出路径有验证；
- 至少一位有经验工程师完成代码评审。

### C6 — 2027-09-12：年度验收

- 两版定向简历、180～220 道代表题、六次模拟面试完成；
- 五至十次试投或真实面试完成；
- 至少两个项目故事可连续深挖 20 分钟；
- 目标 JD 必备项匹配度约 70%。

### C7 — 2027-12-12：可选延长验收

若延长投递窗口，不再新增大主题，只修复面试暴露的最大两个缺口、增强旗舰项目可靠性，并保持每两周至少一次模拟面试或真实流程。
